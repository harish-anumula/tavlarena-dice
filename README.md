# tavlarena-dice

Check for yourself that the dice in a [TavlArena](https://tavlarena.com/) game were not chosen by the server.

TavlArena is a free, ad-free Tavla and backgammon website. Online games use **provably fair dice**: before the first roll, the server publishes a commitment (a hash) to a secret seed. Both players then add their own random contribution. Every roll comes from the seed and both contributions, so the server could not have picked the dice after seeing them. After the game the server reveals the seed, and anyone can recompute every roll with this package.

How it works on the site: [tavlarena.com/fair-dice](https://tavlarena.com/fair-dice/) (the site launches soon).

This package is independent of the website. It has **no runtime dependencies** and never uses the network.

## Verify a proof

On a finished game, download its dice proof (a `proof.json` file), then run:

```sh
npx tavlarena-dice verify proof.json
```

With Node.js 20 or newer installed, nothing else is needed. Output:

```text
Transcript matches the revealed seed and inputs (8 rolls). Publication timing and operator non-peeking are not proved.
```

If anything was changed (a die, the seed, the settings, a player, the order of rolls), it fails:

```text
Verification failed: dice_mismatch
```

Options:

```sh
# Also check that the commitment matches the one you saw before the game started
npx tavlarena-dice verify --expected-commitment <64-hex> proof.json
# Machine-readable output
npx tavlarena-dice verify --json proof.json
# Read from standard input; Turkish messages
cat proof.json | npx tavlarena-dice verify --lang tr -
```

Exit status: `0` verified, `1` the proof is invalid, `2` bad arguments or unreadable input. The seed is never printed. Input is limited to 16 MiB of UTF-8 JSON. The Turkish messages are a draft pending native review.

### What a successful check proves, and what it does not

It proves that the revealed seed, game ID, player IDs and settings hash to the published commitment, and that every listed roll follows from that seed, both player contributions and consecutive roll counters.

It does **not** prove when the commitment was published, who the players really were, when contributions were sent, that the history is complete (dropping the last rolls is not detectable without your own record of the final roll count), or that the operator never looked at the seed. Comparing `--expected-commitment` with the value shown to you before the first roll covers the first point. In a local game the device owner holds the seed, so local verification cannot stop the owner from cheating.

## The scheme (encoding v1)

```text
settingsHash = SHA-256(canonicalJson(settings))
commitment   = SHA-256("tavlarena-dice-commit-v1" || gameId || settingsHash || seat0Id || seat1Id || seed)
block(n, b)  = HMAC-SHA256(key = seed, "tavlarena-dice-roll-v1" || gameId || contribution0 || contribution1 || u32be(n) || u32be(b))
```

IDs are UUIDs as 16 raw bytes; the seed and contributions are 32 bytes each. For roll number `n`, read bytes of `block(n, 0)` left to right, skip any byte from 252 to 255 (so each face is exactly equally likely), and map each kept byte to `byte % 6 + 1`. The first two kept bytes are the two dice; if a block runs out, continue with `block(n, 1)` and so on. Every roll advances `n`, including opening ties and rerolls.

The exact byte layout, canonical JSON rules, proof format and error codes are in [SPEC.md](SPEC.md).

## Independent test vectors

[`vectors/v1.json`](vectors/v1.json) holds canonical-JSON encodings, commitments, 27 HMAC blocks (including the maximum counter and block), 24 rolls, a seed whose first byte is rejected and a tied opening. They are generated by [`vectors/generate.py`](vectors/generate.py), a second implementation using only Python's standard `hashlib` and `hmac`; it imports nothing from this package. The tests check the TypeScript implementation against them, so an implementation in any language can be checked the same way:

```sh
python3 vectors/generate.py   # rewrites vectors/v1.json: same values, possibly different whitespace
```

## Use as a library

```sh
npm install tavlarena-dice
```

```ts
import { verifyTranscript, commitment, roll, hexToBytes } from "tavlarena-dice";

const result = await verifyTranscript(proof, { expectedCommitment });
// { ok: true, rollsVerified, commitment } or { ok: false, errorCode, rollIndex? }
```

Also exported: `canonicalJson`, `hashSettings`, `commitment`, `rollBlock`, `roll`, `secureBytes32`, `uuidToBytes`, `bytesToUuid`, `hexToBytes`, `bytesToHex`, and the types `DiceTranscript`, `DiceRoll`, `DiceErrorCode` and `VerificationResult`. It uses WebCrypto, so it runs in Node.js 20+, modern browsers and Cloudflare Workers. Derivation functions throw `DiceError` with a stable `code`.
